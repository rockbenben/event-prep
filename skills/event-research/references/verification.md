# 查证手册：怎么找到、怎么确认

调研阶段最费时间、也最容易出错的部分。这份是可操作的查证清单。

---

## 穿透第三方票务站

### 特征值提取表

从 URL 和上下文里把这几样先抠出来，后面全靠它们反查：

| 特征 | 例 | 用途 |
| --- | --- | --- |
| 纯数字 ID | `1879040305100` | 搜索引擎精确匹配 |
| slug | `ai-engineer-shanghai-2026` | 拼官网 URL |
| 平台名 | `huodongxing` / `luma` / `eventbrite` | 配 ID 一起搜 |
| 主办方 | `AI Engineer` | 找官方域名 |
| 城市 + 年份 | `Shanghai 2026` | 消歧义 |

### 「读到了」的判据

- ✅ 页面里**有活动标题、日期、地点**等实质内容。
- ❌ 返回 200 但正文是「请登录」「验证中」「暂无内容」。
- ❌ 拿到的是通用页脚 / 推荐位 / 广告。

被挡之后**最多再试一次**（换一种方式：比如加 `?amp`、找 m 站、找缓存）。两次还不行就转检索。

## 检索式清单

按顺序试，命中即停：

```text
"<数字ID>" <平台名>                    # 1. 最精确，先试这个
"<数字ID>"                             # 2. 去掉平台名
"<活动全名>" <城市> <年份>              # 3. 主查询
"<活动全名>" program                   # 4. 找议程
"<活动全名>" schedule OR agenda OR 议程
"<活动全名>" pdf 议程                   # 5. 官方 PDF 议程很常见
"<主办方>" 官网 OR 官网
"<活动全名>" site:<猜测域名>
"<活动全名>" 报名 OR 购票 OR 门票
```

**搜索引擎快照**（缓存副本）在原站挂了时经常能救急，但**要标清它是快照**（快照日期 ≠ 信息日期）。

## 官方信源长什么样

锁定官方站后，按这个顺序找最有价值的东西：

1. **议程页**（`/program` `/agenda` `/schedule` `/speakers`）——信息量最大。
2. **官方 PDF 议程**——常含正式标题、Abstract、房间号。
3. **票务页**——价格、是否售罄、是否需要实名。
4. **公告 / 新闻稿**——日程变更、嘉宾 additions、取消。
5. **官方社媒**——最后时刻通知（开场前一小时改时间很常见）。
6. **FAQ / 行前须知**——签到、行李、录制、饮食、充电。

### 多语言

国际会议常有两套页面：先试 `?lang=en`、`?lang=cn`、`/en`、`/zh`、`/cn`、`?locale=`。

- 中英文标题都拿到 → 正文里保留**原题**，可以加中文括注。
- 官方只提供一种语言 → **不要自己翻译讲者职务和公司名**，用原文。

## 时间的查证

活动时间是最容易出错的一项。

- **时区**：优先看官网页面标注、票面上的时区、或往届同活动的时区推断。拿到就写进 `timezone`（IANA 名，如 `Asia/Shanghai`）。
- **跨天**：确认活动的**最后一天**是几号。`end` 是**含当日**的日期。
- **夏令时**：跨 DST 的日期要留神——「11 月 5 日 09:00 当地」在不同年份对应不同 UTC 时刻。写进构建器后它会按 IANA 时区自动处理，你只要保证时区对。
- 官方的「时间待定」就是待定，**不要按往届推测成事实**（可以标注为推测）。

## 事实的查证

| 事实 | 去哪确认 | 怎么标 |
| --- | --- | --- |
| 日期 | 官网议程 / 票务页 / 公告 | 直写 |
| 地点与房间 | 官网 venue 页 / 议程 | 直写 |
| 票价 | 官方票务页（第三方价格**不要写**） | 直写 + 来源 |
| 是否售罄 | 官方票务页 | 直写；注明查证日期 |
| 讲者与机构 | 官网 speaker 页 + 讲者本人确认 | 直写 |
| 语言 / 同传 | 官网 FAQ / 议程标注 | 直写 |
| 是否需单独报名 | 官网 registration 页 | 直写；**最常被漏的一项** |
| 边会 | 官网 side events 页 / 社区活动页 | 直写 |
| 公司融资 / 估值 | 公司官网 newsroom、权威媒体 | 直写 + 来源；**不写传闻** |
| 开源项目 | 项目 GitHub README / 官网 | 直写 + 来源 |
| 讲者履历 | 讲者本人主页 / 公司页面 / 会议 speaker 页 | 直写 + 来源；**找不到就省略** |
| 讲者头像 | 官方议程页的图片（`npm run fetch:speakers` 抓取） | 抓进 `content/<slug>/assets/speakers/`；**文件缺失构建会失败** |
| 场次摘要 | 官方议程页的 Abstract；官方中文 PDF（如果有） | 中文优先；只有英文就转述，并在页面上标注「非官方中文口径」 |

## 冲突怎么办

1. **先确认是不是「不是同一个东西」**——同名不同年份、不同城市、不同主办方，先消歧义。
2. 真冲突时：**级别高的赢**（A > B > C > D），但**两种说法都写出来**。
3. 写清「以官网为准」，并给两个链接。
4. 冲突涉及**时间 / 地点 / 票务 / 报名状态**时，在正文对应位置就标出来——这正是读者最容易被坑的地方。

```markdown
**待确认**：主论坛开始时间官网写 09:30，第三方票务页写 09:00，
以官网议程页为准（https://example.org/program，检索日期 2026-10-20）。
```

## 时间敏感：距开幕还有几天

调研最后**一定要算一次**「距离开幕 N 天」，它决定行前清单的排序：

- **≤ 7 天**：报名截止、签证、票务核验、行程必须排在最前面；有需要立刻办的，单独拎出来。
- **≤ 30 天**：加上住宿、行程、装备。
- **> 30 天**：加上「关注日程发布」「关注早鸟票截止」这类**未来节点**。

---

## 拿不到可靠信息时

**说清楚限制，不要用看起来完整的文档盖过去。**

- 议程完全没公布 → 正文写「待公布」，其余章节（速览、嘉宾、行前清单）照写，这些不依赖议程。
- 只有一个第三方页面 → 所有事实标 D 级，写明「仅第三方来源，待官方确认」。
- 全网找不到 → 直接告诉用户「查不到这个活动的可靠信息」，别硬写。
