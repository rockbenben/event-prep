# 打印版（临时模式）设计

日期：2026-11-05 · 规模：几个相关的小改动

> 中途追加几条需求（见「追加需求」节）：
> **行前清单默认折叠 + 本机记住折叠状态**、**日程的日期进目录**、
> **过了的日程自动收缩 + 记住收缩状态**、**推荐路线每条也能收缩并记住状态**。
> 几条一起做，共用同一套「展开 / 折叠」逻辑。

## 意图与为什么

活动页把大量信息放在「点开才看」的折叠块里：各天日程（默认只开第一天）、长摘要、
讲者简介、「看这场之前要知道的事」提示、手机上收起的头部信息、目录三级子列表。
读者想一次看全、或打印 / 存成 PDF 带走时，需要一份「全部摊开、去掉交互」的干净视图。

同时，行前清单在手机上会占掉大半屏，读者更希望它默认收起、并且下次打开还记得自己
上次是收是开；目录里只有「日程」一个总入口，多天活动想直接跳到「Day 2」得手动找，
所以日程各天的标题要出现在目录里。

## 目标 / 非目标 / 反目标

- **目标**：页头加「打印版」入口（仅活动页）；进入后所有 `<details>` 展开、纯交互组件隐藏、
  配色改成适合纸面；视图内另给「打印 / 存 PDF」与「退出打印版」；直接按 Ctrl+P
  （包括没进打印版就按）也得到同样的展开效果。
- **非目标**：不做可分享地址、不改构建管线、不新产页面、不自动弹打印对话框、不做 i18n、
  不加前端框架或依赖。
- **反目标**：不丢读者本机数据（清单勾选、自己写的笔记照常显示）；不改 DOM 结构；
  刷新后不留在打印版（临时模式，不写 localStorage）；打印版里不出现「记一笔」输入框、
  提示小圆图标、头像放大、目录抽屉、回到顶部、进度条、倒计时等交互控件。

## 约束

- 改动集中在 `src/assets/site.css`、`src/assets/site.js`、`src/templates/layout.ts`（入口按钮）；
  构建管线（`build.ts` 及模板渲染逻辑）不动。
- `<details>` 必须靠 `open` **属性**展开（标准行为，Chromium / Firefox / WebKit 一致），
  只用 CSS 硬撑 `display` 盖不过浏览器的内部隐藏机制。
- 既有约定不动：站内链接 `tabindex="0"`、消毒白名单、状态 / 倒计时 / 分组的
  服务端与浏览器端双实现（`client-parity.test.ts` 必须继续过）。
- 界面中文；品牌名 `EventPrep` 不变。

## 方案（已选）

- **方案一（已选）**：脚本只做两件事——给 `<html>` 挂 `print-mode` 标记；临时把所有
  `<details>` 设成展开，并记住原本关闭的那些，退出时还原。隐藏清单与配色全部写成 CSS 规则；
  `@media print` 复用同一份隐藏清单，`beforeprint` 兜底处理「没进模式直接 Ctrl+P」。
  - 理由：DOM 不变、本机数据原样保留、以后加组件只需 CSS 补一条选择器、
    三引擎行为稳定、跟项目「通用样式集中在 `site.css`」的习惯一致。
- **方案二（未选）**：脚本逐个改 DOM 并记原状态 → JS 要枚举组件、易漏、`beforeprint`
  要复用同一份枚举、样式两处维护。
- **方案三（已排除）**：构建时多产一份打印页 → 用户已选临时模式，不改构建管线。

## 已定细节

- **入口**：`layout.ts` 的 `.header-actions` 里加一枚图标按钮，跟「目录 / GitHub / 深浅色」
  一排，仅 `showToc`（活动页）时渲染，`title` / `aria-label` 为「打印版」。
- **交互**：点「打印版」进模式，**不**自动弹打印框；视图内给「打印 / 存 PDF」按钮
  （调 `window.print()`）和「退出打印版」，按 Esc 也可退出。刷新即回正常版。
- **展开**：`document.querySelectorAll('details')` 全部 `.open = true`，用 `Set` 记住原本
  关闭的，退出时只还原这些。`beforeprint` 同样展开；`afterprint` 若未手动进模式则还原。
- **隐藏（CSS，`<html class="print-mode">` 与 `@media print` 各写一份，注释标明两份清单须同步）**：
  页头的主题 / GitHub / 目录按钮、目录抽屉、回到顶部、操作按钮、进度条、「记一笔」按钮、
  提示图标按钮、头像放大按钮、导出 note、倒计时、以及对纯动作性 summary 的隐藏。
  - ⚠️ 不能一刀切隐藏所有 `summary`：`.agenda-day-summary`（第几天）和
    `.collapse > summary`（条目名称）是**有用信息，要留**；只隐藏动作性的
    （「展开 N 项」「详情」「摘要」、`.agenda-tip-btn`、`.agenda-note-btn`）。
  - ⚠️ 提示按钮藏掉后正文仍要显示：details 已是 `open`，
    `.agenda-tip-toggle[open] + .agenda-tip-body` 照常生效，与按钮是否可见无关。
- **配色**：打印版与 `@media print` 都强制白底黑字、去阴影 / 去悬浮位移 / 去圆点底色、
  链接加下划线（纸上看不出颜色），卡片保留浅灰细边框以便分区；正文限宽放开到整页宽。
- **读者笔记**：笔记存在 `<textarea>` 里，打印视图下去掉边框与背景、只读观感；
  进入模式与 `beforeprint` 时把高度撑到内容高度，避免长笔记被截断。清单勾选状态照常印出。
- **验收**：`scripts/audit-ui.mjs` 补三条——进入打印版后所有 `<details>` 都开着、
  交互组件不可见、退出后原本关闭的仍是关闭的；本地跑 `npm run typecheck && npm test`、
  `npm run audit:ui`、`npm run audit:real`（布局改动，AGENTS.md 第 5 节的硬门槛）。

## 追加需求（中途提出，已纳入本次实现）

### A. 行前清单默认折叠，本机记住折叠状态

- **默认折叠**：把 `## 行前清单` 的**正文**（那一组 `- [ ]` 复选框及其嵌套内容）
  收进一个原生 `<details class="checklist-fold">`，`h2` 标题留在外面（目录要收得到它），
  `<summary>` 写「展开清单」/ 收起时显示条目数；默认不带 `open`。
- ⚠️ **折叠状态与清单勾选是两回事，别混**：勾选早已存在
  `eventprep:checklist:<slug>`（存的是哪些条目的稳定 id）；折叠状态另存
  `eventprep:fold:<slug>:<键>`（见 C 节——最后统一成一套机制管所有折叠块），
  **按活动分开**，跟笔记、进度、滚动位置同属「读者本机数据，不上传、不同步、不清理」。
  没存过就按默认折叠。
- 读写只在 `site.js` 做（`toggle` 事件存、加载时还原）；服务端构建出的 HTML
  一律是收起的，刷新不闪。
- ⚠️ **打印版 / Ctrl+P 时这一块必须摊开**：打印逻辑会展开所有 `<details>`，
  `checklist-fold` 自然也在其中——「一次看全」不能把清单落下。退出打印版时按
  「原本关闭的才还原」规则收回去（读者上次手动展开过的，退出后仍然是展开的）。
- 折叠块内的复选框 id 由条目文字哈希而来（既有约定），折叠 / 展开不改变它，
  之前打的勾仍然在。

### B. 日程的日期出现在目录

- 现状：议程章节被整段接管，`### Day 1 · …` / `### Day 2 · …` 变成
  `.agenda-day-summary`，**不进目录**（`renderMarkdown` 的 `toc` 里只有「日程」一条）。
- 做法：日程渲染时给每一天的 details 一个**稳定锚点 id**（由当天标题 slug 而来，
  同名去重跟正文标题用同一套规则）；渲染完把「日程各天」作为三级条目补进 `toc`，
  挂在「日程」这个二级条目下面。点一下既跳到那一天、又顺手把那一天的 `<details>`
  展开（否则跳过去是收着的，等于没跳）。
- ⚠️ **各天在目录里直接摊开，不进「展开 N 项」子列表**：用户要的就是
  「看到日期 → 点一下跳过去」，藏进折叠块里等于多绕一道弯。
  实测 Playwright 点它要先展开子列表，直接报「element is not visible」。
  日程通常只有两三天，摊开不占地方；「推荐路线」下面挂五六条**普通**三级标题
  才需要收起来。
- ⚠️ id 去重：多天标题可能只差日期后缀，也可能重名，要用 `uniqueId` 那套计数表，
  避免锚点撞 id；正文标题与日程天标题共用同一张表。
- ⚠️ scrollspy 认的是 `.content h2[id] / h3[id]`，日程天标题是 `<summary>` 不是标题——
  目录里高亮「当前读到哪一天」不在本次范围，只保证「点得到、跳得到、跳过去是展开的」。
- 单测补：日程多天时 `toc` 里出现各天条目且挂在「日程」下；`renderToc` 把它们渲染成
  常开的子列表（不进 `toc-sub`）。

### C. 折叠状态是一套机制管所有折叠块，键是稳定标识，存本机

- 用户原话：「记住日期收缩状态」「推荐路线一、二等也都支持收缩，记住缩放状态」。
- **一处存储**：`eventprep:fold:<slug>:<键>`，值是 `'open'` / `'closed'`。
  三类折叠块共用它，靠**键**区分：行前清单 `checklist`、日程各天 `day-<序号>`、
  推荐路线各条 `route-<锚点 id>`。
- ⚠️ **键是稳定标识，不是显示文字**：日程用**当天的序号**、路线用**锚点 id**。
  作者改个标题措辞、或者活动改期，键都不变——读者记的「第一天收着」还在。
- ⚠️ **「没记过」与「记成收起」是两回事**：没记过 = 用默认（自动规则说了算），
  记成收起 = 读者的主意，不再自动改。所以值有两个，不是布尔。
- ⚠️ **`toggle` 事件是异步的，程序化改 `open` 也会触发它**：不加守卫的话，
  「过期自动收缩」会被记成「读者手动收的」，下次就再也不会按日期自动收放了；
  打印版把全部展开也一样会被误记。做法是 `bindFoldState()`：记住「我们刚设的状态」，
  事件里状态没变就是自己的改动在回声，不写盘；打印版另外用全局 `programmatic`
  标记把整段展开/还原包住。

### D. 过了的日程自动收缩（按访问时刻），今天那天的保持展开

- 用户原话：「比如已经到了1106，1105等过去的日程应该自动收缩」。
- 判定在**浏览器里**做（跟状态 / 倒计时同一口径）：站点可能是昨天构建的，
  到了第二天再看时，收不收得按**访问时刻**算。
- 判据是**活动所在地的今天**（按活动时区算，不是读者本机时区）：
  上海的活动，纽约的读者凌晨打开，看到的也该是上海的 11 月 6 日。
- 「过了」= 那天 `< 活动所在地的今天`；「今天」那天的**保持展开**——
  光把过去那天收起来还不够，否则整个日程全收着，读者看到一排收起的标题。
- ⚠️ **服务端只给第一天加 `open`**（那是「活动还没开始」时的默认），
  到了第二天得由浏览器换成「今天那天」。
- ⚠️ **判不出日期的天一律不动**：判据是标题里**无歧义**的 `YYYY-MM-DD`
  （`agenda.ts` 的 `extractDayDate`）。`11 月 5 日` 这种没有年份的不认——
  跨年会算错一天，宁可不知道。
  ⚠️ 但**判不出日期的天照样能记住折叠状态**：自动规则不管它，
  读者手动收起它是要记住的。
- ⚠️ **读者手动改过的那一天，以读者为准**：不然他特意展开昨天（要补看一场）的话，
  一刷新又被收回去——跟他抢。

### E. 推荐路线下的每条路线收成可折叠条目，默认展开

- 用户原话：「推荐路线一、二等也都支持收缩，记住缩放状态」。
- `variantForSection()` 认「推荐路线」这一节（`variant: 'route'`），
  它下面的三级标题跟「机构与嘉宾」一样收成点开式条目——但**默认展开**
  （服务端带 `open`），因为推荐路线是全篇的产出，读者多半要读。
- ⚠️ **每条路线要进目录**：读者是按自己的角色找路线的
  （「我是做基建的，该看哪条？」），目录里没有就只剩整页滚。
  目录条目是 `depth:3 / kind:'route'`，跟日程各天一样**直接摊开**。
- ⚠️ **机构 / 术语条目不进目录**（目录不该列一串嘉宾名）——只有 route 进。

## 留给实现者的判断

- 打印视图里 `@page` 边距、字号微调等纸面细节，以浏览器打印预览实际效果为准。
- 两处隐藏清单若能用更省维护的写法（例如共用同一段选择器文本，构建时由脚本拼出）
  而不引入新依赖，可以自行采用；否则就按「两份清单 + 同步注释」写。
- 「日程各天进目录」若不想改 `renderAgenda` 的返回签名，可由 `markdown.ts` 在
  `renderAgendaSection` 处既产出 HTML、又往 `ctx.toc` 追加条目（议程章节本来就在
  段这一层被接管），实现者自行选最省改动的那条。
